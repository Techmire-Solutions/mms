# MMS Completed Architectural Milestones

Historical register of architectural milestones closed during MMS migration and modernization. Preserved for reference; active agent rules enforce current invariants rather than carrying historical logs.

## Completed Milestones

- **Tenant frontend extraction complete** (completed 2026-11-27, commit `11359bc9f` + the prior module rounds): every tenant domain feature now lives in its `@mms/mod-*/frontend/tenant` audience — users/notifications/profile (iam), workshops, question-bank, obligations, examinations, reports + dashboard tooling (analytics) and accounting. Accounting was the hardest: the module host declares typed contracts (currency, settings editor, document currency, permissions, faculty lookups, report widgets) so the moved code stays explicit-`any`-free and passes the code-norm ratchet; nine app-origin integration suites carry a documented harness TODO. Only the global `/settings` shell and the platform console remain app-owned by design.
- **Acceptance criterion 10 enforced** (completed 2026-11-27): `check:docs-paths` now fails any living doc that names the retired `apps/frontend/` or `apps/backend/`; `SYSTEM_ARCHITECTURE.md` was repointed to `packages/ui/src`, `packages/fe-core/src` and `packages/modules/{module}/src/frontend/tenant`, and the `docs/README.md` index line dropped its dead path while keeping the historical claim. Two tests pin the rule.
- **Guarded pruner** (completed 2026-11-27): `pnpm prune:dead-copies` (`scripts/prune-dead-copies.mjs`, 4 tests) encodes the prune rules that took two painful attempts to learn — dead means unreachable from the app *and* every test, the copy must be byte-identical at delete time, config-referenced files are never touched, and an active tree aborts with exit 2. Dry run is the default; `--apply` re-verifies each pair immediately before deleting and prints the typecheck/suite commands to prove the result.
- **Dead-source pruning, safely** (completed 2026-11-27): `report:dead-sources` now returns the `dead` set (unreachable from the app *and* every test) and flags duplicates by it, excluding config-referenced files (`src/test/**`, anything a `*.config.*` names, `.d.ts`) after a mid-round pass deleted `src/test/setup.ts` and took the platform suite down. With that rule 36 byte-identical, provably dead copies were removed from `apps/platform-web` (483 → 447 files, dead 49 → 13) and its suite re-ran green (1,248 tests).
- **Full `verify:all` run** (completed 2026-11-27): with the sweep at ~64 s the 48-step run (both suites) became practical; it reported every problem in one pass and the round fixed the one that was not the extraction's — `framer-motion` was declared by `@mms/mod-accounting` but unlinked, so `pnpm install` restored resolution. The remaining findings (a cross-module frontend import and 69 type errors inside the accounting module's frontend) are the in-flight extraction's.
- **`verify:all` mirrors CI** (completed 2026-11-27): the runner now appends the flags CI uses (`--ratchet` for `check:code-norms`/`check:frontend-structure`/`check:forms`, `--tracked` for `check:secrets`) and labels each step with them, after a sweep passed in plain mode while CI's ratchet failed on a 304-line file. The same round proved `check:ratchet-baselines` blocks baseline padding: an attempted 0 → 661 `any` baseline was rejected, so that debt must be typed rather than waived.
- **Money-safety precision** (completed 2026-11-27): the `any` rule in `check-money-safety` now requires the line to name a money value (the same `MONEY_ARG`/`NON_MONEY_ARG` test its `Number()` rule uses), leaving generic `any` to `check:code-norms`. Findings fell 631 → 83 and the remainder are real float-money bugs, e.g. `reduce((sum: any, line: any) => sum + line.debit, 0)` in `AccountingDashboardSnapshots.tsx`, which the extraction introduced and its owner must type.
- **`pnpm verify:all`** (completed 2026-11-27): one command runs the typechecks, every `check:*`/`verify:*` gate (discovered from package.json), both Vitest suites and the script tests, reporting each step's duration and first failure without aborting on the first problem; `--skip-suites` and `--json` variants; documented in AGENTS.md and declared as an advisory (non-CI) entry point in `check:ci-gate-parity`.
- **Docs-path self-repair** (completed 2026-11-27): `check:docs-paths --fix` repoints a moved path when exactly one file in the repo carries that basename and refuses to guess when ambiguous (both behaviours proven on the README); `AGENTS.md` joined the living set. `test:scripts` 165.
- **Living-docs path gate** (completed 2026-11-27): `check:docs-paths` (4 tests, CI-wired) requires every repo path mentioned in `README.md`, `SYSTEM_ARCHITECTURE.md`, `docs/README.md` and `docs/architecture.md` to resolve — from the repo root or from a workspace package for `pnpm --filter` commands. Dated audits, ADRs, `archive/` and the migration blueprint keep their historical paths by policy; the README's index-build command was the first real catch (it still pointed at a script that had moved into `@mms/db`).
- **Matrix gates follow the code** (completed 2026-11-27): `scripts/lib/spec-lookup.mjs` resolves a test-matrix requirement by pinned path first, then by basename across `apps/tenant-web/src` and `packages/modules`, so extracting a domain no longer reports a moved spec as a missing invariant; both `check-examinations-tests` and `check-obligations-tests` use it (150 and 37 scenarios), with the fallback proven by temporarily re-pinning a requirement to a deleted path.
- **PWA closure invariant** (completed 2026-11-27): `check:pwa` no longer counts entry-closure entries as its primary signal — it fails when a host-bridge/provider chunk is precached eagerly (`FORBIDDEN_CLOSURE`, the P8b rule) and treats module route manifests as legitimate, with the raw ceiling raised to 100 and the rationale documented. Verified with `pnpm ci:local:full`, which now also catches formatter and ESLint drift that gate sweeps cannot see.
- **CI gate parity** (completed 2026-11-27): `check:ci-gate-parity` (6 unit tests, CI-wired) requires every `check:*`/`verify:*` script to be invoked by a workflow or `local-ci.sh`, or listed as an explicit advisory exemption with its policy — and fails on a stale exemption. It found `check:fe-core-boundaries`, a real invariant that no CI step had ever run; that gate is now wired. `check:tdd-pairing` stays advisory (AGENTS.md).
- **Module export-map gate** (completed 2026-11-27): `check:module-exports` (CI-wired, 5 unit tests) models Node's exports semantics statically and catches the class where a `.tsx` file sits under a `.ts`-first exports wildcard — invisible to typecheck, fatal to vitest. It takes `--fix` to append the missing explicit entry after a manifest regeneration. First catches: `@mms/mod-iam/frontend/tenant/{UsersPage,lib/usersDescriptor}`, `@mms/mod-obligations/…/{obligationsDescriptor,ObligationsSummary}`, `@mms/mod-question-bank/…/{AutoGrading,PerformanceAnalytics}`. Alongside it: `check:accounting-coverage` now documents **both** coverage runs it needs (app + module), and `check-money-safety` / `check-obligations-tests` were repointed off deleted paths.
- **P9 Cleanup · CI path filters + topology docs** (completed 2026-11-27): workflow `paths:` filters now route domain changes through `packages/modules/**` (six stale `apps/api/src/{accounting,examinations,routes/tenant/examinations,...}` entries removed) and a new `scripts/ci/ci-path-filters.test.mjs` ratchet fails CI when any workflow path filter no longer resolves; `SYSTEM_ARCHITECTURE.md`, `README.md`, `docs/architecture.md` and `mms-structure-naming` §1 describe the vertical-module layout; the auth-integration Redis fake landed with the suite.
- **Platform Console Isolation** (completed 2026-11-27): `apps/platform-web/src/tenant/**` was removed entirely (2,312 files) and the app now lints as `appKind: "platform"` with **zero** tenant-audience imports (`@/tenant/*` and `@mms/mod-*/frontend/tenant/*` both 0); `check:web-app-isolation` is CI-wired and reports a **zero baseline** (no frozen backlog left), and the platform app typechecks/builds on its own shell.
- **P9 Cleanup · Final state** (completed 2026-11-27): root audit reports (11 `CONTACTS_*.md`, `ACTION_COLUMN_REVIEW.md`, `SETTINGS_REVIEW.md`) archived under `docs/archive/`; `.github/CODEOWNERS` refreshed for the vertical-module topology (modules, both web consoles, shared packages, tooling, ADRs); `docs/forms-inventory.md` regenerated (96 form-like files); ADR-020 is implemented: every module-owned tenant surface mounts canonically at `/api/tenant/<module>` via `mountModuleDescriptor`, and the legacy `/api/<module>` mount carries `Deprecation` + `Sunset: Wed, 31 Dec 2026 23:59:59 GMT`; kernel/app-level tenant routes (auth, workspace, uploads, audit, notifications, documents, saved-reports, dashboard, module-access, background-jobs, ai, ws) keep their existing prefixes because they are not module-access gated; the P9 ratchet set is covered by `check-core-packages`, `check-module-boundaries`, `module-audience-boundaries.test.mjs`, `moduleAccessCoverage`, `check-backend-boundaries`, `check:package-boundaries` and `check:web-app-isolation`. The release is a deployable `main` commit (`DEPLOY_SHA`); no package version bump (`mms-release-versioning`).
- **Vertical Module Extraction** (completed 2026-11-26): every backend business domain now lives in a `@mms/mod-*` package under `packages/modules/` — 21 modules (accounting, analytics, attendance, audit, billing, contacts, documents, enrollments, examinations, faculty, hasanat, iam, messaging, notifications, obligations, platform, question-bank, sessions, students, tasks, workshops). `apps/api/src` holds only kernel/composition code; every former cross-domain import is a declared port bound in `apps/api/src/modules/*/adapters.ts`; `apps/api/src` has no business-domain directory, and `check-module-boundaries` / `check-topology` pass.
- **RBAC**: Replaced legacy `role ===` write gates with contract `can()` via `useModulePermissions(manifest)` (`mms-auth-security`).
- **Setup & Prefs**: Migrated all module preferences and lookups to typed relational tables (`mms-fields`, `mms-data-layer`).
- **PG Statement Budgets**: Enforced route-level query budgets on hot paths via `statementTimeoutMs` (`mms-data-layer`).
- **CSRF / Origin Gate**: Enforced strict `Sec-Fetch-Site` and origin validation on all mutation routes (`mms-auth-security`).

- **Soft-Delete System**: Added Category B/C partial indexes, partial unique indexes (`WHERE deleted_at IS NULL`), cascades, and session revocation (`mms-data-layer` §6).
- **Retention Hard-Purge**: Implemented background purge worker in bounded chunks of 500 rows with lock-free `SKIP LOCKED` (`mms-data-layer` §6).
- **4-Locale Translation Parity**: 100% dictionary completeness across all 8,026 keys in en/ar/ur/fa validated via `check:i18n`; zero missing or untranslated fallbacks (`mms-settings-i18n`).
- **Live Push & Aggregates**: Closed across all primary and secondary modules via `genericRelationalService` broadcasting and `invalidateModuleQueries` dispatcher (`mms-core`).
- **Tenant RLS Coverage** (shipped 2026-09-18 in migration `0116_force_rls_missing_tenant_tables.sql`): All 17 active tenant tables carry per-table `ENABLE ROW LEVEL SECURITY` + `FORCE ROW LEVEL SECURITY` + `tenant_isolation_policy` matching the `0076_force_rls_all_tables.sql` pattern (`mms-data-layer` §1).
